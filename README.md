# ShuttleDesk

אפליקציית הסעות עובדים בעברית. פרויקט עצמאי לאחסון ב-Cloudflare Pages עם Supabase Auth ו-Postgres.

## מה נכלל

- מנהל, סדרן ונהג, כניסה עם טלפון וסיסמה אישית שהמנהל מקצה, ללא שירות SMS
- נסיעות איסוף ופיזור, מספר נוסעים, שיבוץ, יעדים, לוח שנה ודוחות
- נהג רואה רק נסיעות ונוסעים שמשויכים אליו, באמצעות הרשאות בצד השרת
- מנהל יוצר חשבונות נהגים וסדרנים
- קוד המקור ניתן להעלאה ל-GitHub ולפרסום אוטומטי ב-Cloudflare Pages

**עדיין לא נכלל:** התראות Push מתוזמנות, סנכרון פעולות נהג ללא אינטרנט, בדיקות עומס ואבטחה מלאות, רישום ביקורת שינויים, חישוב מסלולים. אין להשתמש במערכת עם נתוני עובדים אמיתיים לפני השלמת ההקמה ובדיקות הרשאות.

## התקנה

1. ב-Supabase Dashboard פתח **SQL Editor**, הדבק והרץ את `supabase/001_schema.sql` בשלמותו.
2. ב-**Authentication > Providers > Email**, ודא ש-Email authentication פעיל. אין צורך להפעיל **Phone** או להגדיר Twilio. חשבונות משתמשים נוצרים רק בשרת עם כתובת אימייל פנימית שנגזרת ממספר הטלפון ומאושרת בעת היצירה. במסך הכניסה המשתמש מזין טלפון וסיסמה בלבד. כתובות האימייל הפנימיות אינן משמשות לשליחת דואר או לשחזור סיסמה. העדף סיסמאות חזקות והפעל הגנות נוספות לפני שימוש אמיתי.
3. העלה את הפרויקט לריפו GitHub פרטי בשם `shuttle-desk`.
4. ב-Cloudflare Dashboard צור **Workers & Pages > Pages > Connect to Git** ובחר את הריפו.
   - Build command: `npm run build`
   - Output directory: `dist`
   - Root directory: `/`
5. הגדר את המשתנים הבאים ב-Cloudflare Pages Settings > Variables and Secrets:
   - `SUPABASE_URL`: כתובת הפרויקט
   - `SUPABASE_PUBLISHABLE_KEY`: המפתח הציבורי
   - `SUPABASE_SECRET_KEY`: מפתח שרת סודי של Supabase, כ-**Secret** בלבד
   - `BOOTSTRAP_TOKEN`: מחרוזת אקראית ארוכה (לפחות 24 תווים), כ-**Secret** בלבד, לשימוש חד-פעמי בהקמת מנהל
6. כדי ליצור את חשבון המנהל הראשון, פתח בדפדפן את `https://YOUR-CLOUDFLARE-DOMAIN/setup.html` ומלא שם, טלפון בפורמט בינלאומי, סיסמה ואת קוד ההקמה שהגדרת ב-Cloudflare. לאחר שנוצר מנהל, השירות מסרב להקים מנהל נוסף. מחק את `BOOTSTRAP_TOKEN` מההגדרות אחרי ההקמה.
7. המנהל נכנס באפליקציה עם טלפון וסיסמה, יוצר משתמשים בלחצן `＋ משתמש` ומוסיף נוסעים/נסיעות.

## פיתוח מקומי

```bash
npm install
npm run dev
```

האתר דורש פרויקט Supabase שבו הסכמה קיימת וחשבונות משתמשים מוגדרים. פונקציות השרת של Cloudflare דורשות את המשתנים לעיל גם בבדיקה מקומית. המפתח הציבורי שמוטמע בקוד אינו מעניק גישה לטבלאות בלי התחברות; ההרשאות נאכפות ב-Supabase RPC.

## אבטחה והגבלות ידועות

- אין לשמור `SUPABASE_SECRET_KEY` ב-GitHub או בקבצי `VITE_*`.
- טבלאות הנתונים אינן נגישות ישירות למשתמשים. גישה דרך `read_shuttle_state`, `save_shuttle_state`, `driver_trip_action` עם בדיקת משתמש ותפקיד.
- פעולות מנהל נעשות באמצעות פונקציית Cloudflare מאובטחת, המאמתת את ה-JWT מול Supabase ובודקת תפקיד.
- המבנה הנוכחי של מאגר הנסיעות הוא JSON יחיד עם בקרת גרסאות, מתאים לנפח קטן. אם מספר הנסיעות יגדל מאוד, יש לעבור לטבלאות נסיעות ונוסעים נפרדות.
- קוד אישי קבוע הוא סיסמה, לא SMS חד-פעמי. מספר הטלפון מומר לכתובת אימייל פנימית קבועה לצורכי אימות בלבד, ללא תיבת דואר אמיתית. אין מנגנון שחזור סיסמה כרגע. מומלץ להוסיף איפוס סיסמה על ידי מנהל, MFA ומדיניות סיסמאות לפני שימוש מבצעי.
